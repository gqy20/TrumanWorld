# World Map V1：共享道路拓扑

## 目标

World Map V1 将模拟移动和 3D 舞台从两套互不相干的坐标逻辑，收敛为一份由后端发布的权威拓扑。后端用它计算路线、距离和到达 Tick；前端只负责把同一组节点、边和路线渲染成 Voxel 道路与连续移动。

## 行为契约

- 每个地点占据一个逻辑地块，地点入口位于地块南侧的道路节点。
- 道路不会穿过地点中心；所有入口处于同一张连通图中。
- 相同地点数据无论输入顺序如何，都生成完全一致的拓扑。
- 坐标冲突时按地点 ID 排序后，确定性地放入最近空地块。
- 移动距离等于路线边长之和；持续 Tick 为 `ceil(distance / speed)`，至少为 1。
- 已持久化的 Movement V2 数据没有路线字段时仍可恢复，并继续使用兼容时长。

## API Schema

世界快照 `GET /api/runs/{run_id}/world` 增加：

```json
{
  "navigation": {
    "version": 1,
    "nodes": [{ "id": "road:0:1", "x": 0, "y": 1 }],
    "edges": [{
      "from_node_id": "road:0:1",
      "to_node_id": "road:1:1",
      "distance": 0.5
    }],
    "location_entrances": { "location-id": "road:0:1" }
  }
}
```

在途状态增加：

```json
{
  "route_node_ids": ["road:0:1", "road:1:1"],
  "distance": 0.5,
  "speed": 1.5
}
```

## 坐标规则

场景地点 `(x, y)` 映射到偶数格地块中心 `(2x, 2y)`；道路节点使用至少一个奇数分量的格点，因此天然绕开建筑中心。入口为 `(2x, 2y + 1)`。每条相邻道路边长度为 `0.5` 个世界单位。

前端会将拓扑整体居中，但不会重新规划道路。建筑中心通过入口反推出，地块尺寸和视觉预设来自统一 Voxel Kit；因此换皮不会改变导航语义。

## 后续演进边界

V1 是可复现的正交网格，优先解决权威性、可测试性和路线一致性。未来可在保持节点/边协议不变的前提下加入手工道路、桥梁、楼层、禁行边和 A* 权重，无需重写移动事件或渲染接口。
